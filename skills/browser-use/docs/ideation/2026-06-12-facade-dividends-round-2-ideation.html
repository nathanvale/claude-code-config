Facade dividends — round 2

NEW capabilities the proven N=5 facade + mechanical oracle + cost table unlock — beyond the four already shipped.

2026-06-12 repo-grounded 10 survivors · 44 raw 5 axes builds on live N=5 proof
The substrate is the unlock. This session proved a working N=5 facade with a mechanical differential oracle (a Set diff over independent ground-truth sources — not the LLM), a measured cost table, and transparent failover. That substrate is a platform, and it has dividends nobody designed for. The four proven dividends (cost-routing, oracle, degradation, payload tiering) were just the first layer. These ten push into the surprising ones: consensus as the agent's default perception, Byzantine-fault-tolerant high-stakes actions, engines composed by strength not picked by cost, and a facade that learns from its own runs. Every one is the thinnest mechanism over data we already produce.

Ranked ideas

★ 1

Confidence-annotated perception — every observation carries its agreement score

New agent-nativeConf HighCx M

Instead of handing the agent one engine's DOM, the facade returns each element tagged seen_by: 5/5 or 2/5. The agent acts freely on consensus elements and treats contested ones as "investigate before acting." The oracle already computes who-saw-what — this promotes per-element disagreement from a one-off diff call into the default perception payload.

Scenario: on the Wikipedia page, the 14 authority-control links arrive tagged 2/5 — the agent knows to re-snapshot before trusting them, instead of either missing them (single-engine) or trusting them blindly.

Basis · direct

"consensus + per-element disagreement + who-saw-what" is the proven oracle output; this generalizes it from a diff call to the normal snapshot the agent already consumes.

Why it matters

The agent stops trusting all observations equally — it spends caution budget only on the contested ~10% of the page. This is the oracle becoming the agent's whole way of seeing.

Meeting test: "If your snapshot told you which elements 4 engines missed, would you click them without looking twice?"

★ 2

Stakes dial — agent buys consensus only where it matters

New agent-nativeConf HighCx S

One facade param: snapshot(tier: cheap | consensus). cheap = the measured-fastest engine (40ms, single source). consensus = fan out all 5 + mechanical diff. The agent's planner sets the dial per step — cheap to scroll a list, consensus to confirm the right row before acting. Cost-aware confidence as a knob the agent turns, backed by the cost table.

Basis · direct

Measured cost table exists as data; degradation chain already routes by engine — this exposes the routing knob to the agent instead of fixing it.

Why it matters

Consensus is 5× fan-out — not free. The dial means the agent buys correctness exactly where stakes justify it and runs cheap everywhere else. Makes ★1 affordable as a default.

Meeting test: "Would you pay 5× latency on every scroll? No — so why is consensus all-or-nothing?"

★ 3

Quorum-gated irreversible actions + signed multi-witness receipt

Trust / safetyConf HighCx M

Mark a step stakes:critical (pay, delete, submit). Before firing, k engines independently re-read the critical element (the "$4,200 to acct …891" button + amount) and must agree via the mechanical diff. Agree → commit; disagree → refuse and surface per-engine values. The commit emits a tamper-evident receipt: {intent, critical_values, confirmed_by:[engines], dissent, hash, ts} — paired with the redaction moat so it never leaks raw secrets.

Scenario: one engine reads a late-hydrated DOM showing the wrong amount; the other two disagree; the facade refuses the transfer instead of firing on a mis-rendered page. The receipt later proves "3 engines confirmed $X before transfer."

Basis · direct + reasoned

Verify-after-operate + redaction are named moats; the oracle already does Set-comparison consensus. Byzantine-fault-tolerance: one compromised/stale engine is outvoted. Opt-in on the commit step only (cost).

Why it matters

Turns "the agent thinks it worked" into "≥3 independent ground-truth sources confirm it" for exactly the steps where being wrong is unrecoverable. A guarantee a single engine structurally cannot make — and an audit artifact that survives a dispute.

Meeting test: "For the click that spends money, trust one possibly-stale snapshot, or three engines that must agree?"

★ 4

Drive-observe split — robust engine drives, debug engine watches

Engine-strength compositionConf HighCx M

One task names the robust engine as driver (playwright auto-wait clicks Submit) while the debug engine observes on the same warm Chrome (chrome-devtools captures the network + console + perf for the request that click triggered). The facade emits one combined record: action-from-playwright, side-effects-from-chrome-devtools. Today you pick one and lose either robustness or visibility.

Scenario: the single most common real failure — "the click worked but the backend call 500'd" — becomes one atomic observation instead of two engine swaps.

Basis · direct

playwright = auto-wait; chrome-devtools = 44-tool network/perf. All 5 share one warm Chrome at near-zero marginal fan-out cost — so concurrent drive+observe is cheap.

Why it matters

Turns five engines from redundancy into specialization. The robust hand on the wheel, the debug eye on the glass, same task. No single engine gives you both.

Meeting test: "Which engine drove and which one watched?" — a sentence anyone can say in standup.

★ 5

Reproduce-everywhere — "does this bug hit all 5 engines?"

Oracle generalizationConf HighCx S

The agent hits an anomaly (element missing, action no-ops) and issues repro(intent). The facade replays that exact engine-origin-tagged intent across all 5 and returns a per-engine verdict matrix: "missing on Chrome lineage (2), present on Chromium lineage (3)." The agent instantly knows: real site bug (fails everywhere) vs engine artifact (fails on one lineage).

Basis · direct

The Wikipedia divergence (N4 saw 14 links others truncated) is exactly an engine-lineage artifact this auto-classifies. The oracle generalizes to any observable.

Why it matters

"Is the button gone, or does only my engine think it's gone?" is the single most expensive ambiguity in browser automation — and a single engine literally cannot resolve it. The fleet makes it a mechanical lookup.

Meeting test: "Is the button gone, or does only your engine think it's gone? With one engine you cannot know."

6

Cross-engine verify-after-operate — an independent witness, not self-report

Trust / safetyConf HighCx S

Upgrade the postcondition floor: engine A performs the action, engine B (different lineage) reads the resulting post-state and diffs against A's claim. The guarantee shifts from "the engine that acted believes it succeeded" to "an independent engine confirms the world changed." The acting engine shares the failure mode (stale ref, cached DOM) that caused a bad action — so it's the worst possible verifier.

Basis · direct

Verify-after-operate is a named moat; ref staleness is per-engine. Thin: reuse verify-after-operate, just bind the verify read to a different engine than the operate.

Why it matters

An engine confirming its own success is the weakest evidence. An independent witness turns it into corroboration nearly for free — the natural default under the stakes dial.

Meeting test: "The acting engine said the order went through; the witness still saw an empty cart — we stopped a false success."

7

Cloaking / differential-serving detector — the oracle as a security signal

Trust / safetyConf MedCx S

Fan the same URL across engines whose lineages present different automation fingerprints and diff the content each was served. A site serving materially different DOM/links/prices to different engines trips the oracle — a red flag for bot-detection, cloaking, A/B buckets, or price discrimination, before the agent acts on poisoned content. Same Set diff over normalized content.

Basis · direct

Grounding names "bot-detection serving different content per engine" and "cloaking, A/B variance." The oracle caught real divergence already; this points it at content.

Why it matters

You can't trust a scrape or an automated action if the site is secretly serving your engines different pages. Cross-engine disagreement is the only free signal that the page is lying to you.

Meeting test: "The facade flagged the checkout renders differently to two engines — the site is fingerprinting us and we were scraping a decoy."

8

Self-healing cost table — append-only run ledger replaces the static numbers

Self-improvingConf HighCx S

Every run already produces per-engine latency + success + payload. Append one line per engine-run to runs.ndjson (engine, domain, intent, ms, ok, bytes, ts). Preflight reads the tail and computes rolling p50 + success-rate per (engine, domain) to seed routing — so the hand-measured "40ms/122ms/304ms" table becomes a live measurement that drifts with reality (a Chrome update slows an engine; the ledger catches it next run). One append + one tail-read, no DB.

Basis · direct

Grounding: "we have a measured per-adapter cost table as DATA" and "transport kind does NOT predict latency" — a static table can't track that drift. The 2026-05-30 ideation refused heavy machinery; this stays a flat file.

Why it matters

The benchmark stops being a lie the day Chrome ships an update. Routing uses last week's real numbers, not numbers measured once in May. The compounding foundation the other learning ideas build on.

Meeting test: "Routing uses last week's real numbers, not the ones I measured once in May."

9

Divergence memory — the facade learns its own blind spots

Self-improvingConf MedCx S

Every consensus run produces a who-saw-what diff. Append each disagreement to a thin ledger keyed by URL-pattern + element-role. Next time the agent touches a known-divergent surface (Wikipedia navboxes, lineage-truncated lists), the snapshot arrives pre-annotated "engines historically disagree here — already running consensus." Over time this also down-weights an engine that is chronically the lone outlier on an observable (weighted consensus, not flat majority).

Basis · direct + reasoned

The Wikipedia truncation is a concrete recurring-divergence datum; the oracle emits per-element disagreement. Append + lookup is the thinnest compounding mechanism — no retraining.

Why it matters

Disagreement is currently rediscovered every run. Remembering it means the agent escalates to consensus proactively on known-flaky surfaces instead of getting burned first — and the oracle's vote gets sharper from its own history.

Meeting test: "The facade already knows Wikipedia navboxes make engines disagree — why rediscover that every run?"

10

Mid-task anomaly fan-out — automatic differential diagnosis

New agent-nativeConf MedCx M

When a step is anomalous, instead of escalating to one debug engine, the facade fans the failed step's context to a targeted subset — chrome-devtools for "did the network 500?", playwright for "was the DOM even settled?", agent-browser for "is the interactive set empty?" — and the mechanical diff over their answers localizes the cause. Near-zero marginal cost because they share warm Chrome. The agent gets a one-shot differential diagnosis no single engine could produce.

Basis · direct + reasoned

"5 engines on one warm Chrome = near-zero marginal fan-out." Composes the anomaly trigger with the differential oracle into root-cause localization.

Why it matters

Turns fan-out from a redundancy check into a debugging instrument: "DOM was settled, interactive set was fine, but the network 500'd" — the diagnosis an agent currently can't make at all.

Meeting test: "It failed, three engines weighed in, and we knew which layer broke."

Recommendation

The spine: ★8 (self-healing ledger) is the cheapest, most foundational — it makes everything cost-aware self-correcting and seeds ★9. Then the agent-perception pair ★1 + ★2 (confidence-annotated perception behind a stakes dial) — this is the one that changes how the agent sees, and it's the headline product story: "the agent's perception is consensus-scored, and it pays for confidence only when it matters." Then ★3 (quorum + receipt) for the high-stakes / regulated-action wedge — the guarantee no single-engine tool can make. ★4 (drive-observe split) and ★5 (reproduce-everywhere) are the developer-facing killer demos. ★7 (cloaking detection) is the surprise security angle worth a spike.

The throughline: every one of these is the oracle (a mechanical diff over N witnesses) or the cost table (data) applied to a new surface — perception, actions, debugging, security, learning. The platform was the product; these are what it pays out.
