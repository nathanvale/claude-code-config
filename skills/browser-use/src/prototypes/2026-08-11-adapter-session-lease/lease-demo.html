PROTOTYPE — THROWAWAY

Adapter Session Lease — does the lifetime model feel right?

The question: when browser work runs, the browser tool quietly creates a named background session that nobody ever cleans up — they pile up forever. The proposed fix is a lease: the run takes out the session once at the start, every piece of work reuses it, a login block keeps it alive, and finishing the run hands it back. Cleanup commands come from a small per-tool registry, so the run itself never learns tool commands. Click through and see whether that model survives the awkward cases: a blocked login you resume later, a cleanup that fails, a crash, and the alternative "clean up after every step" rule the current draft code uses.
