01What it is

A skill that designs a command-line interface human-first, script-friendly, against the clig.dev rubric. The design philosophy stays language-agnostic; the recommended way to build the result is TypeScript + Bun on top of @side-quest/cli-command-facade — the runtime that enforces the patterns you designed, so you never hand-roll flag parsing, exit-code mapping, JSON envelopes, or error shapes.

02The pipeline — design → enforce → guard

create-cli and the facade are two halves of one flow. They meet at a single typed object.

create-cli

Nothing merges: the skill is prompt (author-time); the facade is code (runtime). The skill produces the spec and shows the generated code how to consume the package.

04Deliverables

Covered by the contract
  • Command tree + USAGE synopsis
  • Args/flags table (types, required)
  • --json output rule
  • Error + exit-code map
  • Safety: --dry-run / execution modes
  • Destructive-op classification (side-effects)
  • Result schema + follow-up actions
Stays prose (no contract field)
  • Output: --plain, color (NO_COLOR), pager
  • Interactivity: prompts, TTY, --no-input
  • Signals: Ctrl-C, crash-only recovery
  • Config: precedence + XDG dirs; env vars
  • Docs, deprecation, distribution, naming, examples

The facade has no field for these — design them in the prose spec. Backfilling some (config/env, --plain, --no-input) is tracked as a facade issue.

06Wire-up — copy, adjust names

The deliverable is a flat record of contracts plus the few lines that hand them to the facade. defineCommandFacadeContract validates at module load and throws on drift.

import {
  type CommandFacadeContract,
  defineCommandFacadeContract,
} from "@side-quest/cli-command-facade";

type CommandName = "build";
type CommandMutation = "read" | "write";
type ToolCommandContract = CommandFacadeContract<
  CommandName,
  "agent" | "operator",
  CommandMutation
>;

// Key each (sub)command by name — the contract record is flat.
const contracts = {
  build: {
    script: "scripts/build.ts",
    summary: "Build the project.",
    usage: ["build [--out <path>] [--json] [--dry-run]"],
    json: true,
    audience: "agent",
    mutation: "write",
    sideEffects: ["write"],
    executionModes: ["normal", "dry_run"],
    outputModes: ["json", "plain"],
    interactivity: "optional",
    envVars: [{ name: "GIT_DIR" }],
    flags: {
      "--out": { type: "path" },
      "--json": { type: "boolean" },
      "--dry-run": { type: "boolean" },
    },
    exitCodes: {
      "0": "build succeeded",
      "1": "build failed",
      "2": "usage error",
    },
  },
} as const satisfies Record<CommandName, ToolCommandContract>;

// Throws at load if the contract drifts. writeImplyingMutations arms the
// #64 high-stakes guard: a write-ish mutation must declare write/destructive.
defineCommandFacadeContract(contracts, {
  path: "scripts/command-contract.ts",
  writeImplyingMutations: new Set(["write"]),
});

$ bun run scripts/command-contract.ts  ·  bunx --bun tsc --noEmit -p scripts/tsconfig.json

07Validate at construction

Write-and-check collapse into one un-skippable step. The validator enforces shape, not judgment — a minimal legal contract needs only script, summary, usage, json, audience, mutation, flags, exitCodes.

MistakeDrift category caught
enum flag, empty valuescommand-enum-flag-values-missing
flag key without --command-flag-name-invalid
declares a reserved diagnostic flagcommand-reserved-diagnostic-flag
exit code keyed "success" not "0"command-exit-code-invalid
audience outside the closed setcommand-audience-invalid
alias at missing target / empty argscommand-alias-*

Diagnostic flags are facade-owned — --quiet, --verbose, --debug, --run-id are consumed before your command sees argv; declaring one is rejected. --json is not reserved — you declare it and own its rendering.

08What command output actually looks like

The facade writers produce the output; the command supplies only the payload. The observability spine (run_id, duration_ms) is injected by the writer.

{
  "deployed": true,
  "run_id": "01JRUN…RUNID",   ← injected
  "duration_ms": 42          ← injected
}
[
  "item-a",
  "item-b",
  "item-c"
]  ← no run_id/duration spine
{
  "status": "error",
  "run_id": "01JRUN…RUNID",
  "error": {
    "code": "AUTH_REQUIRED",
    "message": "Not authenticated for 'prod'.",
    "exit_code": 4,
    "severity": "error",
    "recoverability": "authenticate",   ← agent acts on this
    "retryable": false,
    "hint": { "summary": "Run the auth flow, then retry.",
             "action": "authenticate",
             "docs_url": "https://docs.example.com/auth" }
  }
}

severity / recoverability / retryable drive agent behavior: retry+retryable:true → retry same input; authenticate/change_input/repair_state → act first; fatal+none → stop, escalate. A result trying to own top-level run_id/duration_ms makes the writer throw CliWriterContractError (exit 70).

10Self-correction loop (autonomous mode)

When an agent emits a contract, pair it with a parse → fix → re-parse loop. parseCommandFacadeContract returns all issues at once, so one pass fixes a batch and re-runs.

emit contract → parse() → ok? ✓ done · issues? apply each action ↺ no fixer? STOP → human

Converges in 1–2 passes for shape errors. Bound it: if a pass applies no fix, stop and hand the action string to a human — the build-time analog of the high-stakes pause. Never spin.
