# Issue 361 - Vault Git V2: durable foreground admission and bounded background completion

Generated by `cli.ts ledger-init --json`. Runtime owns this starting document.
Format and protocol live in `references/ledger-and-helper.md`.

## Acceptance criteria

- [ ] Return one durable opaque task ID within 2 seconds, only after exclusive claim and worker acknowledgement.
- [ ] Join identical concurrent calls to one task and one worker; refuse changed transaction, generation, capability, or input.
- [ ] Keep the existing engine as sole mutation owner and preserve every exact-path, head, lease, activation, capability, and generation fence.
- [ ] Expose task-selected status: state, phase, heartbeat, checkpoint, elapsed time, terminal result, and one next action.
- [ ] Keep public task output free of credentials, capabilities, private paths, auth URLs, raw Git output, and child output.
- [ ] Keep healthy work beyond 30 seconds in_progress; never falsely report remote_unavailable.
- [ ] Distinguish launch failure, lost worker, genuine remote failure, repair_needed, and genuinely unknown.
- [ ] Recover claim-before-spawn, acknowledgement-before-response, restart, and stale-heartbeat cases without duplicate workers, commits, pushes, or lease owners.
- [ ] Align CLI discovery, help, parsing, schemas, and runtime behaviour.
- [ ] Pass real-process admission, concurrency, crash, privacy, guard-falsification, and existing regression suites.
- [ ] Prove one separately approved live exact-path transaction, remote closure, aligned main, and clean-clone vault check.
- [ ] Finish with zero open P0/P1 findings and green hosted CI.
