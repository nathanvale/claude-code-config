15-minute brain version

Loop card first.

The idea is simple: before an AI agent starts repeating work, make it write one clear card that says what it is doing, how it checks itself, when it stops, and what proof it will show.

Like you are 15: A normal prompt is like saying, "Make my room better." A loop card is like saying, "Pick up clothes, put books away, stop when the floor is clear, and send a photo so I know it worked."
Loop card

Give the agent a job, a repeat button, a finish line, and proof.

Why this exists

AI agents are good at doing steps. They are bad when the steps are fuzzy, the finish line is missing, or nobody checks the result.

Vague instruction

"Keep improving this until it is good."

Problem: the agent can spin forever, change random stuff, or say it is done without proof.

Loop-card instruction

"Repeat these steps, check this evidence, stop at this point, and ask before risky changes."

Result: the agent has rails, a finish line, and a receipt.

The whole idea in five boxes

1

You have a goal

"Fix this bug" or "research this topic" is not enough yet.

2

Make a loop card

The card turns the goal into a controlled repeatable loop.

3

Agent runs the loop

It repeats only inside the allowed boundaries.

4

Evidence proves it

Tests, screenshots, traces, or inspected outputs show what happened.

5

Maybe reuse later

If the loop worked, it can become a future example after a human says yes.

The four questions

These are the diagnostic keys. If one is missing, the loop is probably weak.

CYCLE

What repeats?

Name the steps the agent will do again and again.

STOP

When does it stop?

Name the finish line, max attempts, budget, or handoff point.

MECHANISM

How does it work?

Name the tools, checks, context, and decision rules.

EVIDENCE

How do we know?

Name the proof: test output, screenshot, trace, diff, or human review.

What the card holds

The card is not a giant plan. It is the small control sheet the agent reads before it starts looping.

Loop Card

Goal

What result are we trying to get?

Cycle

What steps repeat?

Stop

What ends the loop?

Verifier

What checks the work?

Evidence

What proof gets saved?

Authority

What may change, and what needs a yes?

Example: broken test

Goal: Make the failing test pass.

Loop

Run test, inspect error, edit the smallest relevant code, rerun test.

Stop

Stop when the test passes, or after 3 failed attempts, or when the fix needs product approval.

Proof

Show the final test output, changed files, and what was learned.

The future bit: reuse without chaos

A successful card can become a useful example later. But the MVP does not let the agent silently rewrite the prompt pack.

1

Run worked

The goal completed and the evidence was inspected.

2

Human retro

A person answers: did this actually help?

3

Candidate

The card can be saved as a possible future example.

4

Human gate

Only a clear human yes can promote it into the active pack.

Translation: the agent can suggest learning from success. It cannot quietly change the rules it will use next time.
