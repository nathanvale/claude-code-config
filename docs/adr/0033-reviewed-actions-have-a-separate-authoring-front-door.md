# Reviewed actions have a separate authoring front door

Browser Runbooks orchestrate declarative business steps and may reference a Reviewed Action by id and exact digest, but never contain inline JavaScript or approve executable code. A separate action front door owns machine-readable discovery, validation, source application, effect and origin binding, and human-gated promotion. Agents may author and validate action code; only external human approval can make its exact digest available to an active Runbook Generation, and actions never replace the generic authentication path or receive credential values. Runbook apply requires every referenced action digest to be promoted and available; unresolved compositions remain Runbook Drafts outside the Private Runbook Catalog so one experiment cannot block whole-catalog activation. The Reviewed Action authoring front door is a prerequisite for the Private Runbook authoring front door, ensuring machine-readable action references always have a complete discovery, repair, and promotion path.
