# Runbook authoring validates and applies complete documents

The Browser Use authoring front door exposes a model-derived `runbook schema --json`, then accepts one complete Runbook Draft through `runbook validate --file` and `runbook apply --file`. It does not split metadata across flags and steps across a second file, nor maintain field-level edit and clear semantics. Reusing the runbook document and validator as the sole authoring contract keeps discovery, generated drafts, Git review, CLI acceptance, and catalog bytes aligned. Only the setup-owned source-checkout front door may mutate the Private Runbook Catalog; a packaged runtime may execute the active Runbook Generation but refuses authoring rather than treating its installation or current working directory as writable source. Apply creates an absent target, treats identical content as a no-op, and requires the previously observed record digest before replacing different content, preventing one agent from silently overwriting another agent's change. Delete likewise requires the exact observed record digest; a matching delete removes only the catalog source and leaves the active runtime generation unchanged until later activation.
