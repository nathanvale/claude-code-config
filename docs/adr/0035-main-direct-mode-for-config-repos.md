# claude-code-config and dotfiles commit directly to main behind a complexity-gated review

The PR ceremony (worktree, branch, push, PR, merge) added latency without a second human reviewer: Nathan reviews his own PRs, so the PR was a formality. The two personal config repos, `$HOME/code/claude-code-config` and `$HOME/code/dotfiles` (these checkouts only — a same-named clone stays on the normal rules), now run main-direct mode: all work is built on `main` in the main checkout and committed to `main`. The review gate scales with risk: for complex commits, the agent explains the case for a `compound-engineering:ce-code-review` on the exact final diff and asks the human whether to run it. Approval runs the review and requires findings resolved before commit; declining skips the review and the commit continues. Complex means behavior-changing code, contracts or schemas, startup-instruction or security surfaces (docs included), or multi-file changes touching behavior or policy; splitting a change set into smaller commits never downgrades it; a commit is trivial only when none of those apply (typo, mechanical, non-behavioral doc); when unclear, offer review. A review pass covers only the tree it reviewed; edits after the pass require another human decision before rerunning it. Worktree isolation is dropped in these repos with its known cost: parallel agents share one checkout and can inherit each other's dirty files, so one canonical writer at a time is the operating assumption, mirroring the Super-vault exception. Every other repo keeps worktree isolation, feature branches, and PRs. The pre-commit instruction-health adapter still runs at the commit boundary in claude-code-config. Reverting is one edit each to the AGENTS.md override bullet, the two Claude rule carve-outs (`rules/git-workflow.md`, `rules/worktree-isolation.md`), the `docs/git/worktree.md` exception line, and the `docs/git/workflows.md` carve-outs, then mark this ADR superseded.
