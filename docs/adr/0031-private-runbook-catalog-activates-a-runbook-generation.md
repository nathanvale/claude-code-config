# Private runbook catalog activates a runbook generation

All Browser Runbooks are private operator knowledge authored in one Git-versioned Private Runbook Catalog. Runtime execution never reads mutable authoring files directly: `browser-use runbook activate` validates the complete catalog and its referenced Reviewed Actions, then atomically selects an immutable Runbook Generation under XDG data. This keeps cross-machine sync and review with the private repo while giving execution a complete, rollback-capable snapshot; mutable XDG overrides and package rebuilds are not authoring or activation paths. Read surfaces expose catalog and active digests plus their synchronization status rather than silently choosing one view, while execution always resolves the selected active generation. Activation requires the complete catalog digest observed during review, refuses drift under its catalog lock, and is an idempotent no-op when that digest is already active. The catalog and referenced action bytes must match one Git commit, which the generation records beside its content digest; unrelated working-tree changes do not block activation. Activation is a permanent runbook-family operation, never a migration-family command, and always covers the complete catalog rather than one service or flow. Cutover bootstraps and verifies the first generation before atomically selecting it, then removes the compatibility-XDG and repo/package execution fallbacks; a missing active generation thereafter returns typed activation repair instead of reading unactivated bytes. Public package builds contain runtime code and schemas only: private runbooks and action assets never enter `dist` or a published tarball and reach XDG only through source-checkout activation.
