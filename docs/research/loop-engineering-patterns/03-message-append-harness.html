The Message-Append Harness

The atomic unit of every agentic loop: send, respond, run tool, append, repeat.

Cycle Stop Mechanism
Loop Structure
Send messages
→
Model responds / calls tool
→
You run the tool
→
Append result to messages
→
Repeat
↻ cycles until stop condition
stop_reason = end_turn returned by the API

Before you can design a complex loop, you need to understand the atomic unit all loops are built from: the message-append harness. This is what every agentic framework — Claude Code, LangChain, Codex — implements under the hood.

The pattern is simple enough to fit in five steps, but most "AI automation" tools obscure it behind abstractions that make it harder to debug, not easier.

The five steps

messages = [{"role": "user", "content": initial_task}]

while True:
    response = llm.call(messages)
    
    if response.stop_reason == "end_turn":
        break
    
    # Model wants to use a tool
    tool_result = run_tool(response.tool_use)
    messages.append(response)
    messages.append({"role": "tool", "content": tool_result})

Why this matters for loop design

When you understand the message-append harness, you understand that "loop engineering" is just deciding: what goes into the initial messages? What tools can the model call? What is the stop condition? Everything else is composition of this primitive.

The before/after from @LCSeekers captures the transition perfectly: before Dynamic Workflows, you were manually playing the role of the harness — copy output, paste into next prompt, fix. Now you design the harness and step back.
