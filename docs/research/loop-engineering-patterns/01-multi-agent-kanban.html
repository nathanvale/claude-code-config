The Multi-Agent Kanban Loop

A PM agent breaks goals into tasks, specialised agents execute, a tester closes the arc.

Cycle Mechanism

TL;DR

Split planning, execution, and verification across separate agents. The loop only closes when the tester passes — not when the executor thinks it's done. Kanban state makes every handoff visible and auditable.

The Loop

Goal in
→
PM agent plans
→
Specialist agents execute
→
Tester verifies
→
Done or loop back
↩ On failure: feedback returns to the relevant specialist agent and the arc re-runs
STOP: Tester agent passes — PR opens

How It Works

The multi-agent kanban pattern treats a coding goal the same way a project manager treats a sprint: break it down, assign it to specialists, verify the output, and only close the loop when the work passes review.

The key insight is role separation. A single LLM asked to plan, execute, and verify its own work is like asking a student to grade their own exam. When you split those roles across agents, each one operates in its lane — and the loop closes when the tester says it closes, not when the executor thinks it's done.

What makes it a loop

The tester agent is the STOP gate. If it finds issues, the loop sends feedback back to the relevant specialist agent and re-runs. The PM agent doesn't move to the next task until this arc completes. Kanban state (pending → in-progress → review → done) makes the loop inspectable — you can see where it is at any point.

Implementation sketch

// Pseudocode
while task = kanban.next_pending():
    spec = pm_agent.plan(task)
    result = specialist_agent[spec.role].execute(spec)
    verdict = tester_agent.verify(result)
    if verdict.passed:
        kanban.mark_done(task)
    else:
        kanban.requeue(task, feedback=verdict.feedback)

Why the orchestration surface matters

@akshay_pachaar uses Telegram as the orchestration surface — not because Telegram is special, but because a visible message thread gives the loop an audit trail. Every task assignment, every handoff, every tester verdict is a message you can scroll back through. When the loop fails, you can see exactly where it broke.
