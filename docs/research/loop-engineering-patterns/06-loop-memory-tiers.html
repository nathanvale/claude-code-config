Loop Memory Tiers

A loop without memory resets every run. A loop that learns turns mistakes into rules.

Mechanism Cycle
Loop Flow
Run loop
→
Observe mistakes
→
Convert mistakes to rules
→
Enforce rules on next run
→
Loop improves over time
↺ repeats until stop condition
Stop No new mistakes observed (loop has converged on its rule set)

The most underappreciated dimension of loop design is memory. @PawelHuryn defines three tiers, and the distinction matters enormously for how the loop behaves over time.

Tier 0: No memory

The loop starts from zero every run. Each execution is stateless — the agent has no knowledge of prior runs, prior mistakes, or prior successes. This is the default for most "just run the agent" setups. It's reliable but doesn't improve.

Tier 1: Passive memory

The loop records what happened — logs, outputs, decisions. But it doesn't use that history to change behaviour. This is worse than no memory, because the loop repeats the same mistakes with the confidence of a system that "has memory".

Tier 2: Active learning memory

The loop converts mistakes into mandatory rules that subsequent runs must follow. When the loop fails, a rule is written: don't do X in context Y. On the next run, those rules are injected into the agent's context. The loop improves over time.

# CLAUDE.md entry added after a mistake
# Rule added 2026-06-10: never use git add -A
# Reason: accidentally staged .env file in prior run
# Always stage specific files by name.

@koylanai's reframing is key: "loop is better framed as self-improving context infrastructure." The loop isn't magically intelligent — it's infrastructure that accumulates institutional knowledge as rules, and enforces those rules on every subsequent run.
