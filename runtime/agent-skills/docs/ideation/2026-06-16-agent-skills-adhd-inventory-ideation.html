Ideation: Agent Skills ADHD Inventory

date: 2026-06-16 topic: agent-skills-adhd-inventory focus: repo-local skill projections, blacklist defaults, calm inventory mode: repo-grounded

Grounding Context

This repo has 58 top-level skill directories. That validates the user concern: default-open plus blacklist can become invisible abundance unless the product explains what is visible.

Repo rules say skills are authored only in skills/, and that deploy targets can drift from git visibility. Current install.sh still wires user-global skill surfaces, including ~/.claude/skills and per-skill ~/.codex/skills links. Earlier repo research already points toward .agents/skills/ as the cross-client projection target and says per-vendor symlinks should be fallback, not primary.

The ADHD lens from adhd-helper emphasizes tiny visible actions, reduced decision load, triage buckets, and preserving momentum. External grounding agrees that repo-local skill discovery matters: OpenAI documents Codex scanning repository .agents/skills; Claude documents project-local skill directories; the public skill ecosystem is also growing, with large collections and small composable repos coexisting.

1. Status as a Calm Inventory Map

Make agent-skills status the first-class answer to “what am I getting?” It should show counts, groups, ignored patterns, projection health, and one next action in under one screen.

Axis: Inventory legibility
Basis: direct: this checkout has 58 top-level skill directories; adhd-helper asks for a first visible action and clear mode; OpenAI documents repo skill discovery through .agents/skills.
Rationale: Blacklist defaults are only calm if the visible set is explainable without opening config or reading symlink trees.
Downsides: Needs grouping heuristics and concise output discipline.
Confidence: 92%
Complexity: Medium

2. New Since Last Sync

Keep a small local snapshot of the last projected visible set. On status, show newly visible, removed, and newly ignored skills before the full list.

Axis: Change awareness
Basis: reasoned: ADHD overwhelm spikes when change is silent; a snapshot turns a 58-item inventory into a small diff.
Rationale: The user does not need to inspect the whole catalog every time. They need to know what changed since the last known calm state.
Downsides: A lockfile-like snapshot needs clear wording so it is not mistaken for source of truth.
Confidence: 88%
Complexity: Medium

3. Skill Groups Without Profiles

Group visible skills by lightweight derived buckets such as core, coding, review, product, personal, archive, and fixtures. Do not add user profiles in v1.

Axis: Decision load
Basis: direct: the repo contains active skills, archived skills, fixtures, and workflow families under one catalog; adhd-helper favors triage buckets.
Rationale: Groups make abundance scan-friendly while avoiding profile management, which would recreate hidden global state in a different form.
Downsides: Auto-grouping will be imperfect unless skills later grow explicit categories.
Confidence: 82%
Complexity: Low

4. Explain Why Visible

Add agent-skills list --why. Each row says whether a skill is visible because it matched the default catalog, was not ignored, and has a valid SKILL.md.

Axis: Repair confidence
Basis: direct: AGENTS.md says real deploy-target directories can drift and become invisible to git; current install logic has many implicit symlink ownership rules.
Rationale: “Why can the agent see this?” and “why can’t it see that?” should be explainable without knowing the implementation.
Downsides: Adds a second output mode to keep terse and stable.
Confidence: 80%
Complexity: Medium

5. Ignore Suggestions

Make status suggest likely ignore patterns for archived skills, fixtures, broken skill dirs, and obsolete aliases. The user decides; the tool does not silently curate.

Axis: Noise control
Basis: direct: this repo has skills/archive and fixture skills under the catalog; the user explicitly wants blacklist behavior, not allowlist maintenance.
Rationale: Suggestions make the blacklist easier to start without turning the tool into an opinionated gatekeeper.
Downsides: Needs conservative suggestions to avoid hiding useful skills by accident.
Confidence: 78%
Complexity: Low

6. Repair Script That Says One Thing

When projections are broken, print exactly one repair command, usually agent-skills sync. Details move behind --verbose.

Axis: Repair confidence
Basis: direct: current install status can surface many symlink states at once; adhd-helper says preserve momentum and end with one visible action.
Rationale: Diagnostics should reduce panic, not display every possible cause. The top-level command should be a recovery baton.
Downsides: Some advanced debugging detail moves one command farther away.
Confidence: 76%
Complexity: Low

7. Attention Budget Preview

Show a soft warning when the visible skill set crosses a chosen threshold, for example “Visible skills: 58. This may be noisy. Consider agent-skills ignore suggest.”

Axis: Noise control
Basis: external: large public skill collections now exist, while Matt Pocock's repo positions skills as small and composable; abundance needs a scanning aid.
Rationale: The tool can acknowledge cognitive cost without forcing a hard cap or requiring allowlists.
Downsides: Thresholds can feel arbitrary; keep it advisory and local-configurable only if needed later.
Confidence: 70%
Complexity: Low
