Auto-connect finds CDP. It does not replace CDP.

The name describes how a client discovers and negotiates access to Chrome. Once attached, the client still controls Chrome through the DevTools protocol.

Auto-connect = find + request access → CDP = inspect + control

Three tools, three implementations

Chrome DevTools MCP

--autoConnect requests access to active Chrome. Chrome may ask the operator to allow the connection.

Playwright CLI

attach --cdp=chrome resolves the Chrome channel. Its docs require Chrome's remote-debugging UI setting.

agent-browser

--auto-connect checks profile state, common ports, HTTP discovery, then a direct-WebSocket fallback.

Consequence: one Warm Chrome verdict cannot assume every adapter performed the same handshake. Proof must name the browser-entry mode and the adapter attachment it authorizes.

Why auto-connect is attractive

AdvantageMeaning
Existing sessionReuse current tabs, cookies, extensions, SSO, and MFA state.
No fixed port ceremonyThe adapter discovers the running browser instead of requiring a manually supplied endpoint.
Chrome security modelThe default profile is reached through explicit remote-debugging enablement rather than ignored debug-port flags.
Human handoffMove from manual investigation to agent assistance without recreating the browser state.

Why it cannot be the unconditional default

ConstraintConsequence
Adapter-specific discoveryDocumentation and regressions differ per client.
Operator consentUnattended and background runs may stop at a prompt.
Profile selectionThe chosen active/default profile may expose more browser state than intended.
Multiple agentsCDP permits multiple clients, but clients can still select, navigate, or mutate the same targets.
No stable endpoint contractWarm Chrome cannot invent a WebSocket authority when Chrome does not expose one through legacy discovery.

Preferred policy: prefer auto-connect when the request means “use my current Chrome” and an operator can consent. Prefer explicit generic CDP for unattended, reproducible, or tightly isolated work.

Retrieval check: is auto-connect a replacement for CDP?

No. It is the attachment path that leads a supported client to a CDP session.
